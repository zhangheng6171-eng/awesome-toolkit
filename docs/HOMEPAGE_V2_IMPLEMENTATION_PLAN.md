# 首页 V2 实施方案

> 编写日期：2026-06-04
> 视角：完全不懂技术的普通用户（不懂 GitHub/Docker/Linux/VPS/开源）
> 目标：让用户在 5 秒内理解网站用途，10 秒内找到入口，30 秒内进入部署流程

---

## 一、当前用户路径图

### 1.1 理想路径 vs 实际路径

```
理想路径（我们希望发生的）：
┌────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  首页   │ →  │ 场景匹配  │ →  │ 工具详情  │ →  │ 部署指南  │ →  │ 部署向导  │
│ 5秒理解 │    │ 找到工具  │    │ 了解工具  │    │ 准备部署  │    │ 执行部署  │
└────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘

实际路径（非技术用户）：
┌────────┐    ┌──────────┐    ┌──────────┐
│  首页   │ →  │ 困惑     │ →  │ 离开     │  ← 75% 用户在这里结束
│ 看不懂  │    │ 不知道点哪│    │ 关掉标签页│
└────────┘    └──────────┘    └──────────┘
                    ↓ (25%)
              ┌──────────┐    ┌──────────┐    ┌──────────┐
              │ 随便点一个 │ →  │ 看不懂   │ →  │ 离开     │  ← 又流失 60%
              │ 工具卡片  │    │ 工具详情  │    │          │
              └──────────┘    └──────────┘    └──────────┘
                    ↓ (10%)
              ┌──────────┐    ┌──────────┐    ┌──────────┐
              │ 点开始匹配│ →  │ 设备向导  │ →  │ 得到推荐  │
              └──────────┘    └──────────┘    └──────────┘
                                   ↓ (4%)
                              ┌──────────┐    ┌──────────┐
                              │ 工具详情  │ →  │ 部署页面  │  ← 最终 0.3%
                              └──────────┘    └──────────┘
```

### 1.2 每步流失分析

| 步骤 | 进入人数 | 流失原因 | 剩余 |
|------|---------|----------|------|
| 首页首屏 | 100 | — | 100 |
| 5 秒理解网站用途 | 100 | 无 Hero 区，品牌名含技术黑话 | 25 |
| 找到有效入口 | 25 | 搜索框最显眼但不知道搜什么；CTA 太小 | 10 |
| 进入推荐/工具页 | 10 | 50 个工具卡片信息过载 | 4 |
| 工具详情页 | 4 | 工具页有部署 CTA，但用户可能不信任 | 2 |
| 进入部署页面 | 2 | 部署页有技术门槛（服务器/SSH/Docker） | 0.5 |
| **最终部署完成** | **0.3** | | **0.3%** |

### 1.3 四个关键页面的用户视角

#### 首页 `/`

```
用户看到什么：
  "GitHub 精选工具库"                    ← 不知道 GitHub 是什么
  "从全世界开源代码中..."                 ← 不知道开源代码是什么
  [搜索框：搜索工具名称...]                ← 不知道有什么工具可以搜
  [50] [8] [9] [33]                     ← "许可证类型"什么意思？
  "不知道从哪个工具开始？"                 ← 第一个能理解的句子
  ↓ 50 个工具卡片（Ollama/n8n/Immich...） ← 名字都看不懂
  "小李：太爽了！"                        ← 一看就是假评价
  [订阅邮件输入框]                        ← 滚动到这里的人不到 20%
```

#### 推荐向导 `/recommendations`

```
用户看到什么：
  "找到最适合你的工具"                     ← 清晰
  "根据你的设备配置，智能推荐"              ← 有点抽象
  4 步设备选择向导                        ← 设计不错，但流量太少
  "推荐说明" 4 个小卡片                    ← 用了 "Docker" 术语
```

#### 工具详情 `/tool/[id]`

```
用户看到什么：
  "Ollama" + GitHub Star数 + 许可证       ← 顶部信息偏技术
  "在自己电脑上运行 AI..."                 ← 描述对小白友好 ✅
  "⚡ 一键部署到你的服务器"                 ← 部署 CTA 突出 ✅
  "使用步骤：1. 2. 3. ..."               ← 步骤清晰 ✅
  同类工具推荐                             ← 有用 ✅
```

#### 部署页 `/deploy/[id]`

```
用户看到什么：
  "一键部署 Ollama"                       ← 清晰 ✅
  "前置准备：1. Linux 服务器 2. 安装 Agent" ← 对非技术用户有门槛
  服务器推荐链接（阿里云/腾讯云/Vultr）      ← 变现钩子
  "⚡ 开始部署向导"                        ← CTA 突出 ✅
  "或者手动使用 Agent 命令行（高级用户）"    ← 分割用户群
  服务器配置要求 + 环境变量 + 管理命令       ← 技术内容多
```

**关键发现**：工具详情页和部署页本身设计合理，问题出在首页无法把用户送到这两个页面。

## 二、模块逐项审计

### 审计标准

每个模块回答 3 个问题：
1. 非技术用户能理解吗？（能/勉强/不能）
2. 它能推动用户走向部署吗？（推动/中立/阻碍）
3. 它占据的首屏空间值得吗？（值得/中立/浪费）

### 2.1 导航栏 Header

| 子元素 | 能理解？ | 推动部署？ | 空间价值？ | 判定 |
|--------|---------|-----------|-----------|------|
| 品牌名「GitHub 精选工具库」 | ❌ 不能 | 阻碍 | 浪费 | **修改** |
| 副标题「从全世界开源代码中...」 | ❌ 不能 | 阻碍 | 浪费 | **删除** |
| 导航链接「工具对比」 | 勉强 | 中立 | 中立 | **保留** |
| 导航链接「一键部署」 | ✅ 能 | 推动 | 值得 | **保留+突出** |
| 导航链接「反馈」 | ✅ 能 | 中立 | 中立 | **保留** |
| 导航链接「关于」 | ✅ 能 | 中立 | 中立 | **保留** |
| 右侧说明「收录标准：Star≥1000...」 | ❌ 不能 | 阻碍 | 浪费 | **删除** |

**判定详情**：
- 品牌名「GitHub 精选工具库」→ 改为「好工具一键装」（移动端）/「好工具一键装 · 开源工具库」（桌面端）
- 副标题 → **删除**，用 Hero 区的一句话价值主张替代
- 「一键部署」→ 用 primary 颜色（蓝色填充 pill），与其他灰色导航链接区分
- 「收录标准：Star≥1000...」→ **删除**，非技术用户不需要知道收录标准

### 2.2 搜索框 SearchBar

| 分析维度 | 结论 |
|----------|------|
| 非技术用户能理解吗？ | 勉强 — 知道搜索是什么，但不知道搜什么 |
| 推动部署？ | ❌ 阻碍 — 作为页面第一个交互元素，暗示用户"你应该搜索"，但新手不知道该搜什么 |
| 空间价值？ | 浪费 — 占据首屏最宝贵的位置 |

**判定**：**移动位置 + 修改**

- 从首屏 Hero 区移除
- 下沉到场景区下方、工具列表上方
- 添加热门搜索标签（`照片备份` `密码管理` `网站监控` `AI 聊天` `文件同步` `去广告`）
- 点击标签 = 自动填入搜索词 + 筛选

### 2.3 统计卡片 StatCard

| 卡片 | 能理解？ | 推动部署？ | 空间价值？ | 判定 |
|------|---------|-----------|-----------|------|
| 收录工具 50 | 勉强 | 中立 | 浪费 | **删除**（合并到社交证明行） |
| 分类数 8 | 勉强 | 中立 | 浪费 | **删除** |
| 许可证类型 9 | ❌ 不能 | 阻碍 | 浪费 | **删除** |
| 对小白友好 33 | 勉强 | 推动 | 可保留 | **删除**（合并到社交证明行） |

**判定**：**全部删除**

4 个统计卡占据首屏 ~200px 高度（移动端占 2 行），其中「许可证类型」对非技术用户完全无意义。有用信息（50 个工具、33 个适合小白）合并为 Hero 下方一行轻量文字：`50+ 工具 · 30+ 无需编程基础 · 完全免费`。

### 2.4 设备推荐 CTA（蓝色卡片）

| 分析维度 | 结论 |
|----------|------|
| 能理解？ | ✅ 「不知道从哪个工具开始？」是首页唯一一个非技术用户能完全理解的句子 |
| 推动部署？ | ✅ 推动 — 引导到 /recommendations 设备向导 |
| 空间价值？ | 值得 — 但位置太靠后（被搜索框+统计卡挤压） |
| 视觉突出度 | ⚠️ 不够 — 蓝色背景但高度只有一行卡片 |

**判定**：**修改 + 移动位置**

- 从统计卡下方提升到 Hero 区，作为主 CTA 按钮
- 不再是一条小横幅，改为 Hero 区的大按钮
- 文案保持不变（已经是首页最好的文案）

### 2.5 筛选面板 FilterPanel

| 分析维度 | 结论 |
|----------|------|
| 能理解？ | 勉强 — 「按分类」「按安装难度」「按适合人群」标签本身可理解，但分类名（AI & 自动化）对非技术用户还是抽象 |
| 推动部署？ | 中立 — 帮助浏览但不主动引导 |
| 空间价值？ | 中 — 左侧边栏占用 25% 宽度 |

**判定**：**保留**（不变）

筛选面板不在首屏（需滚动才能看到），对已经开始浏览工具的用户有价值。不做改动。

### 2.6 工具卡片列表（50 个 ToolCard）

| 分析维度 | 结论 |
|----------|------|
| 能理解？ | ⚠️ 个体卡片描述清晰，但 50 个一起呈现导致选择瘫痪 |
| 推动部署？ | 中立 — 卡片底部链接是「📖 查看普通人使用方法」，不是「部署」 |
| 空间价值？ | 中 — 卡片列表在页面中下方，需要滚动 3-4 屏才能看完 |

**判定**：**保留**（不变，但位置不变）

工具卡片本身设计合理（名称+描述+标签+难度+链接）。问题不是卡片本身，而是上方缺乏引导。加上场景区和 Hero 后，卡片列表作为「探索更多」区域出现，角色从「主要内容」变为「备选入口」。

### 2.7 用户评价（假评价）

| 分析维度 | 结论 |
|----------|------|
| 能理解？ | ✅ 能理解（中文好评） |
| 推动部署？ | ❌ 阻碍 — 一看就是假的，损害整个网站的信任度 |
| 空间价值？ | 浪费 — 3 张卡占 ~200px 高度 |

**判定**：**删除**

3 条评价（小李/王同学/老马）全正面、无具体细节、头像用彩色圆圈+首字母（经典假头像模板），任何用户看到都会打折扣。在获取真实用户评价之前，不如不放。

### 2.8 邮件订阅 WaitlistForm

| 分析维度 | 结论 |
|----------|------|
| 能理解？ | ✅ 「订阅更新，第一时间获得新工具推荐和早鸟优惠」 |
| 推动部署？ | ✅ 收集邮箱 = 后续转化机会 |
| 空间价值？ | 值得 — 但目前在页面最底部，< 20% 用户看到 |

**判定**：**移动位置**

- 从工具列表下方移动到场景区下方、工具列表上方
- 文案改为：「📬 订阅更新，第一时间获得新工具推荐。前 100 个订阅者未来可享全部功能」
- 增加稀缺性：「已有 XX 人订阅」

### 2.9 Footer

| 子元素 | 判定 |
|--------|------|
| 「工具数据来自 GitHub 公开仓库...」| **删除** — 技术黑话 |
| 「收录标准：Star ≥ 1000...」| **删除** — 同上 |
| 「推荐工具」按钮 | **保留** — 有用的次级 CTA |

### 4.1 Hero 区（新增）

```
┌────────────────────────────────────────────────────────────┐
│                                                            │
│               🚀 好工具，一键装到自己的电脑上                 │
│            不用懂代码，不用学 Docker，5 分钟搞定              │
│                                                            │
│       ┌──────────────────────┐  ┌──────────────────┐       │
│       │  🪄 告诉我用什么设备    │  │  📦 浏览全部工具   │       │

│       └──────────────────────┘  └──────────────────┘       │
│                                                            │
│          💻 我只有 Windows 电脑 · 能装啥？                   │

│          50+ 工具 · 30+ 无需编程基础 · 完全免费              │
│                                                            │
└────────────────────────────────────────────────────────────┘
```

**三行内容**：
1. **主标题**：一句话说清网站是什么（32px bold）
2. **副标题**：排除顾虑 + 承诺简单（18px gray）
3. **双 CTA**：主按钮（设备匹配）+ 次按钮（浏览全部）
4. **轻量入口**：「我只有 Windows 电脑」→ 跳转 `/recommendations?platform=windows`
5. **社交证明行**：50+ 工具 · 30+ 无需编程基础 · 完全免费

**不为零的实现细节**：
- 主按钮用蓝色填充（`bg-blue-600`），次按钮用白色边框（`border border-gray-300`）
- 「我只有 Windows 电脑」用小号蓝色文字链接，放在双按钮下方
- 社交证明行用 13px 灰色文字，前面加一个绿色小圆点

### 4.2 场景区（新增）

位于 Hero 区和邮件订阅之间。3 列卡片，移动端堆叠。

```

│              或者，你想用来做什么？                           │
│                                                            │
│  ┌──────────────────┐ ┌──────────────────┐ ┌─────────────┐ │
│  │       📸          │ │       🤖          │ │     🔐      │ │
│  │ 备份手机照片       │ │ 让 AI 自动干活    │ │ 管理所有密码  │ │
│  │                  │ │                  │ │             │ │
│  │ 把照片存在自己     │ │ 把「收邮件→存附件  │ │ 密码存在自己   │ │
│  │ 电脑上，手机自动   │ │ →发通知」串成一条  │ │ 服务器上，手机 │ │
│  │ 备份，不限容量，   │ │ 自动化流程，像搭   │ │ 电脑自动填充， │ │

│  │                  │ │                  │ │             │ │

│  │ ⏱ 5 分钟         │ │ ⏱ 3 分钟         │ │ ⏱ 3 分钟    │ │
│  │ ⭐ 很简单         │ │ ⭐⭐ 简单         │ │ ⭐ 很简单    │ │

│  │                  │ │                  │ │  warden  →] │ │
│  └──────────────────┘ └──────────────────┘ └─────────────┘ │
└────────────────────────────────────────────────────────────┘
```

**设计要点**：
- 标题用 `或者，你想用来做什么？`（口语化，降低防御心理）
- 每张卡片 = 场景描述（非技术语言）+ 所需设备 + 时间 + 难度 + CTA 按钮
- 按钮文案用「用 [工具名] 搞定→」（动作导向，比「查看详情」好）
- 点击卡片任意位置（或按钮）→ 跳转 `/tool/[id]`，带到部署 CTA 区域
- 3 个场景：Immich（照片）/ n8n（自动化）/ Vaultwarden（密码）

**为什么选这 3 个**：
- Immich：最广泛的个人需求（人人都有手机照片）
- n8n：展示"自动化"这个差异化场景（竞品 awesome-selfhosted 没有）
- Vaultwarden：Bitwarden 兼容，密码管理是刚需
