# 首页 V2 改造方案

> 编写日期：2026-06-04
> 目标用户：非技术普通人（不懂 GitHub/Docker/Linux/VPS）
> 核心问题：当前首页是为「知道自己要什么的技术用户」设计的，非技术用户 10 秒内无法理解网站用途
> 约束：不新增功能、不新增页面、不重构。只优化现有首页的文案、布局、信息架构。

## 二、Hero 区改造方案

### 2.1 当前问题

首页没有 Hero 区。用户打开后第一眼看到的是导航栏 + 搜索框 + 统计卡。没有任何一个元素在回答「这网站是干什么的」「为什么我需要它」。

导航栏标题「GitHub 精选工具库」和副标题「从全世界开源代码中，挑出最好用的工具，配好普通话使用说明」包含 3 个技术黑话（GitHub、开源代码、普通话使用说明），非技术用户全部看不懂。

### 2.2 新 Hero 文案（3 个备选方案）

**方案 A：场景驱动（推荐）**

```
🚀 好工具，一键装到自己的电脑上
不用懂代码，不用学 Docker，5 分钟搞定
[告诉我用什么设备，帮你挑 →]  [看看有哪些工具 →]
```

- 「一键装到自己的电脑上」— 直接回答"这网站是什么"
- 「不用懂代码」— 排除最大顾虑
- 「5 分钟搞定」— 承诺简单快速
- 双 CTA 覆盖两种用户：想被引导的 + 想自己逛的

**方案 B：结果驱动**

```
🏠 把你的电脑变成全能家庭服务器
备份照片、管理密码、运行 AI — 不用写一行代码
[开始匹配工具 →]  [浏览 50+ 工具 →]
```

- 「家庭服务器」— 给用户一个身份认同
- 「备份照片、管理密码、运行 AI」— 3 个具体场景
- 「不用写一行代码」— 排除顾虑

**方案 C：价值主张驱动**

```
⚡ 开源软件，从此不再难装
50+ 精选工具，配中文教程，一键部署到任何设备
[推荐适合我的工具 →]  [浏览全部工具 →]
```

- 「开源软件，从此不再难装」— 短而有力
- 「中文教程」— 对中文用户的差异化价值
- 「任何设备」— 暗示灵活性

**推荐方案 A**。理由：
- 非技术用户最关心「我能不能搞定」，A 直接回答了这个焦虑
- 「一键装」是可想象的动作（无需理解 Docker/容器/部署）
- 「帮你挑」降低选择焦虑

## 三、两个新入口设计

### 3.1 入口 1：「我只有 Windows 电脑」

**为什么需要**：大量用户从「软件推荐」类内容进入网站，他们的第一反应是「我能在自己电脑上装吗？」。当前网站没有直接回答这个问题。

**位置**：Hero 区双按钮上方或下方，作为第三个轻量入口。

**设计**：

```
┌─────────────────────────────────────────────────────┐
│ 💻 我只有一台 Windows 电脑                           │
│    → 推荐可以在 Windows 上直接用的工具（无需服务器）    │
└─────────────────────────────────────────────────────┘
```

点击后跳转到 `/recommendations?platform=windows`，DeviceWizard 预设平台为 Windows。

**改动范围**：
- `HomeClient.tsx`：在 Hero 区添加一个浅色文本链接或小型卡片，链接到 `/recommendations?platform=windows`
- `DeviceWizard.tsx`（或 `/recommendations` 页面）：读取 URL query param `platform`，预设选择

### 3.2 入口 2：「推荐适合我的工具」

**为什么需要**：当前蓝色 CTA 卡片文案是「不知道从哪个工具开始？」，但它只是一个链接。新入口需要更直接地引发行动。

**设计**：这就是方案 A 的主 CTA 按钮「告诉我用什么设备，帮你挑 →」，替换当前的小型蓝色 CTA 卡片。

两个入口的关系：
- **主 CTA**：「告诉我用什么设备，帮你挑」— 引导到 `/recommendations`（4 步设备向导）
- **辅助入口**：「我只有 Windows 电脑」— 快捷键，预设平台，跳过向导第一步
- **次级 CTA**：「浏览全部工具」— 滚动到下方工具列表

## 四、真实使用场景区设计

**场景区的作用**：用户带着问题来（"我想备份照片"），通过场景区找到答案（"Immich 可以"），然后点击进入。

## 五、其他优化项

### 5.1 统计卡片 → 删除或下沉

当前 4 个统计卡：「收录工具 50」「分类数 8」「许可证类型 9」「对小白友好 33」

**问题**：
- 「许可证类型」对非技术用户毫无意义
- 「50 个工具」在社交证明行里说就够了，不需要独占一个卡片
- 4 个卡片占据首屏黄金位置

**方案**：删除统计卡区域，将有用信息（50+ 工具、33 个适合小白）合并到 Hero 下方的社交证明行。

### 5.2 假评价 → 替换为场景区

当前 3 条假评价（小李/王同学/老马）位于工具列表下方。

**问题**：明显造假，损害信任。

**方案**：删除假评价区，替换为第四节的场景区（放在 Hero 下方，工具列表上方）。等有真实用户数据后，在邮件订阅区旁边展示「已有 X 人成功部署 Y 个工具」。

### 5.3 邮件订阅 → 提升到工具列表上方

当前邮件订阅在 50 个工具卡片和假评价之后，用户几乎看不到。

**方案**：将订阅区移到场景区下方、工具列表上方，文案改为：

```
📬 订阅更新，第一时间获得新工具推荐
前 100 个订阅者未来可享全部付费功能
[输入邮箱] [订阅]
```

### 5.4 搜索框 → 下沉，添加热门标签

当前搜索框是页面最突出的交互元素，但新手不知道该搜什么。

**方案**：
- 搜索框从 Hero 区移除，放在场景区下方、工具列表上方
- 添加可点击的热门搜索标签：`照片备份` `密码管理` `网站监控` `AI 聊天` `文件同步` `广告屏蔽`
- 点击标签 = 输入对应关键词 + 触发筛选

### 5.5 导航栏品牌名 → 去技术化

当前：`GitHub 精选工具库`

**方案**：改为 `好工具一键装`（移动端短品牌名）或保留当前名称但把副标题删掉（缩小导航栏高度）。

1. `page_view` 总数 / 独立 session 数 = 平均浏览深度
2. 场景卡 `tool_click` 占比 vs 直接搜索 `tool_click` 占比
3. `wizard_open` 触发率 = wizard_open / page_view
4. 邮件订阅数（WaitlistForm submit）

| 想法 | 排除理由 |
|------|----------|
