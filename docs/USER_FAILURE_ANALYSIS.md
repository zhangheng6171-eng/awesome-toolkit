# 小白用户失败分析

> 审计日期：2026-06-08
> 方法：模拟"不懂技术的小白用户"视角，逐步走完部署流程
> 目标用户画像：有基本电脑操作能力，不懂 Linux/SSH/Docker/端口

---

## 一、用户旅程地图

```
首页看到「一键部署」→ 点进工具详情 → 看到要求 → 进入部署向导
  → 填写服务器 IP → 粘贴 Token → 点击开始部署 → 等待 → 看到完成
  → 打开浏览器访问 → 成功看到工具页面
```

**理想：7 步，3-5 分钟。实际：每一步都有坑。**

---

## 二、逐步骤失败分析

### Step 0：到达部署页面之前 — "我没有服务器"

| 用户想法 | 实际情况 |
|---------|---------|
| "一键部署？是不是点一下就行了？" | 需要先有一台 4GB Linux 服务器 |
| "什么是服务器？" | 网站推荐了阿里云/腾讯云/Vultr，但全是链接 |
| "阿里云轻量服务器多少钱？" | 没有价格说明，用户不敢点 |
| "我只有一台 Windows 笔记本电脑，能用吗？" | 网站没有明确说"不能"的地方 |

**失败概率：~70%。超过一半的小白用户在第一步就卡住了。**

**改进建议：**
- 在部署页顶部加一句大白话：「你需要一台 24 小时开机的电脑（服务器），推荐花 ¥50/月租一台云服务器」
- 给 Windows 用户一个明确的提示：「只有 Windows 电脑不能用一键部署，但可以先装 Docker Desktop 在本地尝试」
- 加服务器购买比价表

---

### Step 1：SSH 登录服务器 — "什么是 SSH？"

| 用户看到 | 用户想法 |
|---------|---------|
| 「SSH 登录你的服务器」 | "什么是 SSH？在哪里输入？" |
| 没有截图 | "怎么连到服务器？" |
| 终端是黑底白字 | "这是黑客用的吗？我是不是搞错了？" |

**失败概率：~80%。毫无 Linux 经验的小白在这一步几乎必然放弃。**

**改进建议：**
- 添加图文教程：Windows 用 Putty / macOS 用终端
- 在部署向导中直接提供 Agent 安装方式，跳过 SSH
- 或者：提供一个「用微信扫码连接服务器」的方案（QR code + 网页终端）

---

### Step 2：安装 Agent — "这是什么东西"

```
curl -fsSL https://awesome-toolkit.pages.dev/agent/install-agent.sh | bash
```

| 用户想法 | 实际情况 |
|---------|---------|
| "这行字要复制到哪里？" | 需要粘贴到 SSH 终端 |
| "粘贴后按什么？" | 按回车 |
| "看不懂英文输出" | install.sh 的输出是中英混合 |
| "卡住了，不敢关窗口" | 可能在下载 Docker 镜像，需要等 1-2 分钟 |

**失败概率：~60%。能 SSH 登录的小白有一半会卡在这里。**

**关键问题：**
- 用户不知道"终端"是什么
- 用户不知道命令粘贴后要按回车
- 用户不知道等待是正常的
- 用户看到红色文字（错误高亮）会恐慌

---

### Step 3：填写部署向导 — "Token 是什么"

部署向导要求填写：
1. 服务器 IP
2. Agent Token（生成后给用户）
3. 可选环境变量

| 用户想法 | 实际情况 |
|---------|---------|
| "Token 是什么？从哪里找？" | 需要先安装 Agent 才能生成 Token |
| "环境变量是什么？" | 完全不懂 |
| "数据库密码要填什么？" | immich 需要 DB_PASSWORD，默认值 changeMe123! 看起来不安全但不知道怎么改 |

**失败概率：~50%。Token 的概念对小白完全陌生。**

---

### Step 4：部署进行中 — "转圈转了 5 分钟了"

部署向导显示终端日志：
```
⏳ 正在检查 Docker... ✓
⏳ 正在下载镜像... [进度条]
⏳ 正在启动服务... ✓
✅ 部署完成！
```

| 用户想法 | 实际情况 |
|---------|---------|
| "下载镜像卡在 50% 不动了" | Docker hub 在国内很慢 |
| "等了 5 分钟没反应" | 有些镜像首次下载确实需要时间 |
| "出现了红色错误信息，我是不是搞砸了" | 可能是非致命的 warning |

**失败概率：~30%。网络慢 + 无进度提示导致用户提前中断。**

---

### Step 5：部署完成 — "我怎么打开它？"

部署完成提示：
```
🔗 访问地址: http://你的服务器IP:2283
```

**Vaultwarden 专用问题：**
| 用户想法 | 实际情况 |
|---------|---------|
| "打开网页了！...但什么都没发生" | 需要先创建账号，但 SIGNUPS_ALLOWED=false |
| "点了注册按钮，说功能已关闭" | P1 修复后默认关闭注册 |
| "网站上说要先改配置，怎么改？" | 需要 SSH 回去改 docker-compose.yml |
| "手机上 Bitwarden App 连不上" | 手机 App 要求 HTTPS，HTTP 无法连接 |

**Stirling PDF 专用问题：**
| 用户想法 | 实际情况 |
|---------|---------|
| "打开网页了！要输入密码" | DOCKER_ENABLE_SECURITY=true |
| "密码是多少？" | **没有任何地方告诉用户默认密码** |
| "试了 admin/admin，123456，都不对" | 用户放弃 |

**Immich 专用问题：**
| 用户想法 | 实际情况 |
|---------|---------|
| "网页打开了！让我创建账号" | ✅ 这一步是 OK 的 |
| "手机 App 怎么用？" | 需要填服务器地址 http://IP:2283 |
| "App 提示连接失败" | 可能是 HTTP 被 iOS/Android 限制 |

**失败概率：~40%。**

## 三、三大工具的小白友好度排名

### 排名 1：Stirling PDF（相对最简单）
- ✅ 1 个容器
- ✅ 低内存（512MB）
- ✅ 网页操作直观（拖 PDF 进去处理）
- ❌ 安全模式无默认密码 —— **致命**
- ❌ 不知道在哪改密码

**修复后评分：⭐ 很简单**

### 排名 2：Vaultwarden
- ✅ 1 个容器
- ✅ 极低内存（256MB）
- ✅ 网页注册流程清晰
- ❌ HTTP 无法用于手机 App —— **致命**
- ❌ SIGNUPS_ALLOWED 需要手动改
- ❌ DOMAIN 配置小白不懂

**修复后评分：⭐⭐ 简单**

### 排名 3：Immich（最复杂）
- ❌ 3 个容器 —— 小白完全不懂
- ❌ 需要 4GB 内存 —— 贵
- ❌ 需要 50GB 硬盘 —— 贵
- ✅ 注册流程简单
- ✅ 手机 App 支持 HTTP

**评分：⭐⭐⭐ 中等**

## 四、TOP 5 最常见的用户失败路径

### 失败路径 1：连 SSH 都不会
```
用户从首页 → 点「一键部署」→ 看到「需要 Linux 服务器」
  → 点阿里云链接 → 买了个服务器 → 不知道怎么连上去
  → 放弃（约 60% 用户）
```

### 失败路径 2：部署后打不开
```
用户成功部署 → 复制 http://IP:8080 到浏览器
  → 浏览器打不开（防火墙没放行端口）
  → 以为部署失败了 → 放弃（约 20% 用户）
```

### 失败路径 3：不会用
```
用户成功部署 + 打开 → Vaultwarden 需要创建账号但注册关闭
  → 不知道怎么办 → 放弃（约 10% 用户）
```

### 失败路径 4：HTTPS 问题
```
用户成功部署 Vaultwarden → 电脑网页能用 → 下载手机 App
  → 输入服务器地址 → 连接失败（需要 HTTPS）
  → 以为 App 坏了 → 卸载 → 放弃（约 5% 用户）
```

### 失败路径 5：不知道默认密码
```
用户部署 Stirling PDF → 打开网页 → 要求输入密码
  → 没有任何地方告诉密码 → 放弃（约 5% 用户）
```

## 五、一句话总结

| 工具 | 一句话 |
|------|--------|
| Stirling PDF | 离"下载即用"只差一个默认密码说明 |
| Vaultwarden | 离"真正能用"只差 HTTPS |
| Immich | 离"一键部署"还很远（3 容器 + 4GB + 50GB） |

**核心洞察：对小白用户来说，最难的从来不是代码，而是"不知道下一步做什么"。**
